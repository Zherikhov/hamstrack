# Architecture Decision Records (ADR)

A log of the significant architectural decisions of the Hamstrack project. One file = one
decision: **what** was decided, **why**, what the **alternatives** were and what
**price** we pay for it.

## How to use it

- One ADR — one decision. The numbering is continuous (`NNNN-kebab-title.md`).
- After the status `Accepted` the file is **not rewritten**. Changed your mind — file a new
  ADR and mark the old one `Superseded by ADR-XXXX`.
- An ADR is **why this branch of the fork was chosen**. It does not replace the specs
  (`docs/design/` — *what* we are building) and does not replace the list of rakes in `CLAUDE.md`
  (*how not to do it*). Overlaps are possible.
- Write an ADR only about significant forks — about what is expensive to roll back or what
  will make a new participant ask "why is it like this?".

## The origin of this log

ADRs 0001–0008 were recorded **retrospectively on 2026-08-22**: the decisions were made
earlier (the exact dates are not recorded in the sources), and their rationale was extracted
from the already existing project documentation — first of all from `CLAUDE.md`.
Each ADR names its source. No facts were made up: if a detail of a
decision is not in the documentation or the code, it did not get into the ADR.
