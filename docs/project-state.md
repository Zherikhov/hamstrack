## Admin console & global taxonomy (M1, 2026-07-15)

**System role**: `users.system_role` (`ADMIN`/`USER`, enum `SystemRole`, extensible). `User.getAuthorities()` → `ROLE_<role>`; all of `/api/admin/**` is guarded by one `hasRole("ADMIN")` line in SecurityConfig. The `seed.admin` account is promoted to ADMIN by `DataSeeder` (idempotent). `/auth/me` returns `systemRole`; the SPA shows "System administration" in the user menu and guards `/admin/**` client-side.

**Taxonomy model** (V6, replaces per-workspace copies): global catalog — `statuses`, `priorities` (NEW entity, was the `IssuePriority` Java enum; `issues.priority_id` FK), `issue_types` — each with `scope_workspace_id NULL` (=global; the `scope_workspace_id`/`scope_project_id` columns are now LIVE for delegated admin — see the **Delegated admin** section below) and `archived_at`. Reusable bindings: `workflows` (+`workflow_statuses` position = board column order, +`workflow_transitions`, `from_status_id NULL` = "from any") and `priority_sets` (+items with `is_default`). `projects.workflow_id`/`priority_set_id` NULL = the `is_system_default` row. `ProjectConfigService` is the ONLY place that resolves effective config (statuses/transitions/priorities/default/validation) — issue paths and the public endpoint go through it. Transition semantics: a source status with no source-specific rules is open; with rules, allowed = its targets + wildcard targets (wildcards grant, never restrict).

**API**: public `GET /api/workspaces/{ws}/projects/{p}/config` (effective taxonomy — the SPA renders board/forms exclusively from it); admin CRUD under `/api/admin/{statuses,priorities,issue-types}` (+`/archive`,`/unarchive`, `DELETE ?replaceWithId=` remaps issues), `/api/admin/{workflows,priority-sets}` (upserts replace children wholesale), `/api/admin/projects` matrix + `PATCH /{id}/bindings`. Integrity guards (409): delete-in-use without replacement, empty workflow/set, workflow change/status removal that would strand issues in statuses invisible to the board. Removed: workspace-scoped `/statuses`, `/issue-types`, `/status-transitions`; `priority` filter/fields became `priorityId`, `IssueResponse.priority` is now an object (id/name/color/icon/position). Workspace creation no longer seeds taxonomy.

**Frontend**: `/admin/**` (lazy `pages/admin/AdminArea.tsx` — own light sidebar under the global top bar; pages: Statuses, Priorities+sets, Issue types, Workflows, Projects matrix; shared bits in `pages/admin/common.tsx` incl. usage chips and the delete-with-remap dialog). Priority icons = lucide names in the catalog `icon` column, rendered by `PriorityIcon`/`PriorityBadge` (`components/ui.tsx`).

**Gotchas**: don't use `CHAR(n)` in migrations — Hibernate validate fails on bpchar (bit us again in V6; V2 had fixed the same thing). Boot 4: no auto-configured `ObjectMapper` bean; `AutoConfigureMockMvc` lives in `org.springframework.boot.webmvc.test.autoconfigure`. Frontend: **never use Tailwind `max-w-2xs…max-w-3xl`** — our `@theme --spacing-{2xs..3xl}` scale shadows them in Tailwind v4, so `max-w-xl` resolves to `var(--spacing-xl)` = **32px** (word-per-line paragraphs); use inline `maxWidth`. React Router: inside a splat route (`/admin/*`) relative `<Link>`/`<NavLink>` paths resolve AFTER the splat — use absolute paths.

## Auth rate limiting (2026-07-14)

`common.ratelimit` — two in-memory mechanisms (single-node; move to Redis if Cloud scales out), both configurable via `app.rate-limit.*` (env `RATE_LIMIT_*`, `enabled` default `true`): **per-IP fixed window** (default 15 req/min) across login/register/verify-email/resend-verification/forgot-password/reset-password, enforced by `AuthRateLimitFilter` — registered via `FilterRegistrationBean` with explicit URL patterns (NOT `@Component`, see filter gotcha) at highest precedence, POST only (`/refresh`+`/logout` excluded: cookie-driven, called on every page load); and **per-account exponential login backoff** (5 fails → 30s, doubling, cap 15 min; success resets) in `AuthService.login`, keyed by submitted email even for unknown accounts (no enumeration via the limiter). Both raise `RateLimitedException` (429 + `Retry-After`, dedicated `GlobalExceptionHandler` handler). Client IP = rightmost `X-Forwarded-For` entry (Caddy ≥2.5 discards client-supplied XFF; only Caddy is exposed on prod) else `remoteAddr`. Counter eviction via `@Scheduled` (`@EnableScheduling` on the app class). Tests: `AuthRateLimitTest` (Boot 4 note: `AutoConfigureMockMvc` lives in `org.springframework.boot.webmvc.test.autoconfigure`).

## Demo data (2026-07-14)

Every user gets a "Demo Workspace" with a "Demo Project" (key `DEMO`, 20 dev-team-style issues — 2 epics with children, mixed types/statuses/priorities/due dates, some assigned to the user) seeded on their **first successful authentication**. `common.seed.DemoDataService.seedOnFirstLogin(userId)` is called from `AuthController` after `verify-email`, `login` **and** `refresh` (refresh matters: after a data reset, users with a live session never hit `/login`). It runs *after* the auth transaction commits and is wrapped in try/catch — a seeding failure never fails the authentication, and the claim rolls back so the next auth retries. Idempotency/race safety: `users.demo_seeded_at` (`NULL` = pending) is stamped by the atomic claim `UserRepository.claimDemoSeed` (`UPDATE … WHERE demo_seeded_at IS NULL`); only the winner seeds. Seeding reuses `WorkspaceService`/`ProjectService`/`IssueService`, so all normal invariants hold. Toggle: `app.demo.seed-on-first-login` (env `DEMO_SEED_ON_FIRST_LOGIN`, default `true`).

**Test-mode data reset** (repeatable while the app is in test mode): add a migration that wipes user data and re-arms seeding with this block: `DELETE FROM issues;` (first — `issues.workspace_id` has no cascade), `DELETE FROM workspaces;`, `DELETE FROM notifications;` (they only reference users and would point at deleted issues), `UPDATE users SET demo_seeded_at = NULL;`. Do **not** rewrite existing migration files — Flyway checksum validation would fail on every already-migrated DB (prod, local) unless its volume is dropped. Attachment blobs are orphaned by a reset (rows cascade, files don't) — clear the storage dir/volume manually if it matters. (The former `V5__demo_data_reset.sql` was folded away by the schema squash below.)

## Schema baseline — migrations squashed (2026-08-07)

The former `V1`..`V12` Flyway chain was **consolidated into a single `V1__init_schema.sql` baseline** (done while the product had zero real users). The new `V1` is the exact final schema the old chain produced — verified by `pg_dump` parity (byte-identical DDL) + seed-row-count match + a `contextLoads` boot on a fresh DB (Flyway migrate → Hibernate `validate` → context up). New schema changes continue from `V2` onward.

**Because a squash changes `V1`'s checksum and drops `V2..V12`, every existing DB must be recreated** — Flyway would otherwise fail checksum/missing-migration validation. Required one-time action per environment: **drop and recreate the database** (local `hamstrack` DB; **prod: drop the `postgres` data volume** so Flyway applies the baseline fresh — attachment blobs in `attachments_data`/S3 become orphaned, clear if needed). This was only safe because there was no production data to preserve.

Notable finding baked into the baseline: `issues.type_id` / `issues.status_id` carry **no FK** (the original V1 FKs were dropped by V6's `DROP TABLE … CASCADE` and never recreated; integrity is app-layer via `ProjectConfigService`). The baseline preserves this exactly (a comment marks it) — re-adding those FKs is a separate, deliberately-tested change. The historical migration-number references in the Gotchas (V2 CHAR fix, V9 `issue_seq` resync, etc.) are now historical; the entity-mapping lessons still apply and the baseline already reflects them.

**Post-squash chain (V2–V6) — number-collision caution:** after the V1 baseline, new migrations resumed: `V2__issue_hierarchy`, `V3__system_fields`, `V4__search_indexes`, `V5__saved_filters`, `V6__custom_field_search_indexes`. ## Advanced search & HQL (HD-21 core, HD-52 custom fields)

Global search is a **fully implemented** feature — NOT a stub (older docs/api-*.md wording that calls it a stub is stale). Package `com.hamstrack.search`.

**Endpoints** — `SearchController` at `/api/workspaces/{wsId}/search`:
- `POST /` — run HQL. `SearchRequest {query (≤2000 chars, ""=all), page, size (default 50, clamped 1..100)}` → `PageResponse<SearchResultRow>` (`SearchResultRow {IssueResponse issue, projectId, projectKey, projectName}`, reuses the board/backlog `IssueResponse`). 422 on parse error (carries highlight `position`) or semantic error (carries `field`).
- `GET /schema` — `SearchSchemaResponse {fields, keywords, values}` for autocomplete; `values` embeds STATUS/TYPE/PRIORITY + per-custom-field `CUSTOM:<key>` picklists (members deliberately not embedded).
- `GET /suggest?field=&q=` — bounded (≤20) member typeahead for user-valued fields (`assignee`/`reporter`/USER custom field). `SuggestResponse {field, suggestions[]}`.

**Query language** (`parser/HqlParser` recursive descent over `parser/Lexer`): boolean `NOT > AND > OR` (left-assoc), parens, optional trailing `ORDER BY key [ASC|DESC], …`. Empty = all. Predicates `field OP value` / `field IN (…)` / `field IS [NOT] EMPTY`; operators `= != > < >= <= ~` (`~` = text match). Values must be quoted strings, numbers, or functions (`currentUser()`, `now()`, `startOfWeek()`) — a bareword raises a targeted "must be quoted" 422. DoS limits (constants in `HqlParser`): query ≤2000 chars, nesting ≤32, IN-list ≤200, ≤5 sort keys, ≤50 leaf predicates. System fields (`FieldRegistry`): `status type priority assignee reporter parent text created updated due` (`label` registered but not-yet-queryable → 422, hidden from `/schema`). `priority` supports ordered comparison via catalog `position` (inverted so `priority > "Low"` = more urgent; `ORDER BY priority DESC` = most-urgent-first). `text ~ term` = `LOWER(title|description) LIKE %term%` (escaped). `created`/`updated` = inclusive-day UTC windows; `due` = real DATE.

**Custom fields (HD-52):** any non-archived `field_def` reachable via a visible project's effective field set becomes queryable by its `key` — **a system field always wins** on name clash. Each predicate compiles to a correlated `EXISTS` over `IssueFieldValue` filtered by `field_id`, with per-type JSONB Criteria functions (`jsonb_scalar_text|numeric|date`, `jsonb_exists`/`?` for MULTI_SELECT membership) registered via a `JsonbFunctionContributor`. `!=` on a scalar = `NOT EXISTS(=)` (absent counts as not-equal); `IS EMPTY` = no value row. SELECT/MULTI_SELECT accept option label or id. Custom fields **non-sortable** in MVP (ORDER BY → 422). Backing indexes: V4 (composite `issues` indexes leading `workspace_id`), V6 (GIN on `issue_field_values.value`).

**Tenancy (critical):** `SearchScope` is a Criteria predicate builder — `workspace = :ws AND project.id IN :visibleProjectIds` (the workspace's **non-archived** projects; empty set → match-nothing, never "all"), ANDed as the **outermost** conjunction on both page and count queries. Membership gate (`resolveWorkspace`) returns **404** whether the workspace is missing or the caller isn't a member (never 403). Name/member/custom-field resolution derives from the same visible-project set, so nothing resolves through a hidden project; all user input is bound parameters (injection-safe).

**Frontend:** `pages/SearchResultsPage.tsx` (route `/w/:wsId/search`), `components/TopSearchBar.tsx` (HQL box + `/schema` autocomplete; hidden without workspace context), `components/SavedFiltersPanel.tsx`. **No `app.search.*` config** — always-on, gated purely by membership; no DC/Cloud difference.

## Saved filters (HD-26, V5)

Table `saved_filters` (V5): `id`, `workspace_id` (FK, ON DELETE CASCADE), `owner_id`, `name VARCHAR(120)`, `hql VARCHAR(2000)`, `shared BOOLEAN DEFAULT FALSE`, `created_at`/`updated_at` (+`set_updated_at()` trigger), UNIQUE `(workspace_id, owner_id, name)`, indexes `(ws, owner)` / `(ws, shared)`. Package `com.hamstrack.search.filter`.

**Endpoints** — `SavedFilterController` at `/api/workspaces/{wsId}/filters`: `GET /` (own + shared), `POST /` (owner = caller; HQL validated at save; 409 on name conflict; `CreateSavedFilterRequest`), `GET /{id}` (own or shared), `PATCH /{id}` (owner only; partial `{name?, hql?, shared?}`; re-validates HQL only if changed), `GET /{id}/usage` (`SavedFilterUsageResponse` — **always empty in MVP**, a delete-with-usage hook for future board/report consumers), `DELETE /{id}` (owner only). `SavedFilterResponse {id, name, hql, shared, ownerId, ownerName, mine, createdAt, updatedAt}` (`mine` caller-relative).

**Semantics** (`SavedFilterService`): `shared=false` private (owner-only); `shared=true` read-only to every other member. Reads of another owner's private filter → 404; mutations by a non-owner (even on a shared filter) → 404 (never 403). **Save-time validation is parse + structural only** (`HqlParser.parse` + `HqlValidator` against the caller's context, so custom fields validate too); **value resolution is deferred to run time** on purpose — `currentUser()`/project-visibility resolve for whoever *runs* it, and a later-archived catalog row must not permanently break a saved query. Stored HQL is only parsed here (executed later via the search engine, bound params). All reads workspace-bound (404 membership gate). Guards: `SavedFilterNameBlankException`, `SavedFilterNameConflictException`, `SavedFilterNotFoundException`. Frontend: `components/SavedFiltersPanel.tsx` inside `SearchResultsPage` (load → runs it; "Edit query" loads body without running).

## Delegated admin — scoped catalog (supersedes M1's "reserved for future")

**Built and in prod.** The catalog is now three-scoped; `scope_workspace_id`/`scope_project_id` are LIVE (mutually exclusive by DB CHECK in the V1 baseline). `issue/entity/Scoped.java` is implemented by Status, Priority, IssueType, FieldDef, Workflow, PrioritySet, FieldSet, IssueTypeSet.

- **GLOBAL** (both null) — the **system admin** (`hasRole("ADMIN")`).
- **WORKSPACE** (`scopeWorkspaceId` set) — the workspace's **OWNER/ADMIN**.
- **PROJECT** (`scopeProjectId` set) — the project's **MANAGER**.

**Roles:** `workspace/entity/WorkspaceRole` = **OWNER, ADMIN, MEMBER** (workspace-level, distinct from the system role). `scope/ScopeResolver`: `requireWorkspaceAdmin` (membership → 404 else; then ≥ADMIN → 403 else, `InsufficientWorkspaceRoleException`); `requireProjectAdmin` (workspace + project membership → 404 else; then ≥MANAGER → 403). **Tenancy rule (explicit):** non-membership and non-existence both 404; a member lacking the role (already knows it exists) gets 403. `scope/ScopeContext {workspaceId, projectId, ancestorWorkspaceId}`: `stamp(entity)` marks a new row at the current scope; `owns(entity)` = exact-scope (edit/delete gate); `canSee(entity)` = global ∪ ancestor-workspace ∪ own-project (visibility / usage-aggregation gate — keeps usage counts from spanning tenants).

**Endpoints:**
- Global: existing `/api/admin/**` (`AdminCatalogController`, `AdminWorkflowController`, `AdminFieldController`, `AdminProjectController`, `AdminUserController`), `ScopeContext.global()`.
- Workspace: `WorkspaceAdminController` at `/api/workspaces/{wsId}/admin/**` — full catalog CRUD (+`/archive`,`/unarchive`, `DELETE ?replaceWithId=`), workflows, priority-sets, issue-type-sets, fields (`DELETE ?dropValues=`), field-sets, `/{id}/usage`, and the binding matrix (`GET /projects`, `GET /binding-options`, `PATCH /projects/{projectId}/bindings`). Each handler: `requireWorkspaceAdmin` + `ScopeContext.workspace(wsId)`.
- Project: `ProjectAdminController` at `/api/workspaces/{wsId}/projects/{projectId}/admin/**` — same CRUD project-scoped + `GET/PATCH /bindings` + `GET /binding-options`. `requireProjectAdmin` + `ScopeContext.project(...)`.

All three consoles share the `Admin*Service`s + `ScopedProjectAdminService`. `BindingOptionsResponse {workflows, prioritySets, fieldSets, issueTypeSets}` where each `SetOption {id, name, scope}` tags GLOBAL/WORKSPACE/PROJECT so the UI marks inherited (read-only) options. `UpdateProjectBindingsRequest {workflowId, prioritySetId, fieldSetId, issueTypeSetId}` (NULL = system default).

**Scoping semantics** (`AdminCatalogService`/`AdminFieldService`): **list** = own-scope rows + inherited (global/workspace) rows **read-only** (`findAllVisibleTo`); global console sees `findAllAtScope(null,null)`. **Create/edit/delete** only rows at the caller's **exact** scope (`findByIdAtScope` → 404 else) — a workspace admin can never touch a global row, a project admin never a workspace/global row. **Uniqueness** checked visible-to (409 "already exists or is inherited — reuse it"). **Usage detail** filtered by `scope.canSee` so a delegated console's counts/lists never span other tenants. Global-only guards preserved (e.g. issue-type delete refuses to empty the base global catalog).

**Frontend:** `pages/settings/WorkspaceSettingsArea.tsx` (route `/w/:wsId/settings/**`; Projects[matrix]/Statuses/Workflows/Issue types/Priorities/Fields; MEMBER role redirected away), `pages/settings/ProjectSettingsArea.tsx` (route `/w/:wsId/p/:projectId/settings/**`; Taxonomy[bindings]/… ; MANAGER-only; invalidates `projectConfig`), `ProjectBindingsPage`, `WorkspaceProjectsMatrix`. All **reuse the system-admin catalog pages** (`pages/admin/Admin*Page.tsx`) via an `AdminApiProvider` context (`makeAdminApi('/workspaces/{ws}/admin')` or `.../projects/{p}/admin` with a `scope`).

## Issue hierarchy (V2)

`V2__issue_hierarchy` adds `issue_types.hierarchy_level SMALLINT NOT NULL DEFAULT 1` (higher level = higher in the tree). Seeded: **Epic=2**, Story/Task/Bug=1, a new global **Sub-task=0** (icon lucide `git-branch`, color `#64748B`, appended to the system-default "All types" set). **Rules** (`IssueService`): a parent/child edge is legal only under **strict adjacency** — the parent type must sit exactly one level above the child (`parentLevel - childLevel == 1`, `violatesAdjacency`), enforced on create (`requireLegalParentLevel`) and update (setting a new parent, or a type change that would make the retained parent illegal → 422). Cross-project parents rejected (`findByIdAndProject`; foreign/unknown → 422). Cycle guard walks the ancestor chain (max depth 20). All parent/type validation runs **before** any mutation (avoids the `@Version` double-write flush trap). **On delete:** direct children are **orphaned to root** (`parent = null`), not re-homed to the grandparent (gap-2 would violate adjacency). `IssueResponse` carries `parent` (`ParentRef {id, key, title, typeId}`), `childCount`, and `Rollup {childCount, doneChildCount}` (batched, no N+1); create/update take `parentId` (+ `clearParent` on update).

## CI/CD

- CI/CD is two workflows (multi-stage `Dockerfile`). **`build.yml`** — `build-and-test` runs on every push / PR (builds + tests against a Postgres service container); `build-and-push` then publishes to `ghcr.io/zherikhov/hamstrack` on pushes to `main` and on release tags `v*` only, after tests pass. **Image tags:** `main` → `latest` + `sha-<commit>` (rolling — the owner's prod tracks `latest`); a `vX.Y.Z` git tag → `X.Y.Z` + `X.Y` (semver, for self-hosters to pin; `latest` is NOT re-pointed to releases). **Versioning is git-tag-driven:** `pom.xml` carries a `0.0.0-DEV` placeholder and is never hand-bumped — `build.yml` computes the version (the tag, else `git describe`) and passes it as the `APP_VERSION` Docker build-arg, which the build stage applies via `versions:set` so `build-info` (About dialog / `/api/meta`) reports it. **To cut a release:** `git tag vX.Y.Z && git push origin vX.Y.Z`. **`deploy.yml`** — owner-only; triggered by `workflow_run` after a successful `Build` on `main` (release-tag builds don't deploy — prod already has that code from `main`), it reaches the server via **AWS SSM** (SSH port 22 is closed — see `docs/ops-prod-hardening.md` §3), running an `AWS-RunShellScript` command that does `cd /opt/hamstrack && docker compose -f docker-compose.prod.yml pull && up -d --remove-orphans && docker image prune -f`. A red `Build` blocks the deploy. Required repo secrets: `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` (region `eu-north-1`; the deploy IAM user may only run `AWS-RunShellScript` on the one instance, whose id is **inlined** in `deploy.yml` — not secret, and a mistyped secret would be masked as `***` and 403). The old SSH-based `SERVER_HOST`/`SERVER_USER`/`SERVER_SSH_PRIVATE_KEY` secrets are obsolete. The server keeps `docker-compose.prod.yml`, `Caddyfile`, and `.env` in `/opt/hamstrack`. The `app` service is config-lean: it pulls the operator's whole `.env` via `env_file: .env` (so every app var flows through without being re-declared in compose) and sets only two things explicitly under `environment:` — `SPRING_PROFILES_ACTIVE` (the `cloud`/`dc` switch, `${SPRING_PROFILES_ACTIVE:-cloud}`) and the internal `DB_URL` (points at the `postgres` compose service, never overridable). The `postgres` service uses `${DB_USERNAME:?…}`/`${DB_PASSWORD:?…}` fail-fast so a missing credential aborts `up` with a clear message instead of a cryptic later failure. `.env.prod.example` is the full template — it covers every variable the app reads: `GITHUB_OWNER` (lowercase!), `SPRING_PROFILES_ACTIVE` (`cloud`|`dc`), `DB_USERNAME`/`DB_PASSWORD`, `JWT_SECRET`, `SEED_ADMIN_EMAIL` **and** `SEED_ADMIN_PASSWORD` (the admin is seeded only when *both* are set — a blank email skips seeding, see `DataSeeder`; `SEED_ADMIN_DISPLAY_NAME` optional), `APP_BASE_URL` (must be the real public URL — email links, robots/sitemap, OG tags default to `http://localhost:8080` otherwise), `SITE_ADDRESS` (the domain(s) Caddy serves + gets certs for — the `Caddyfile` is templated as `{$SITE_ADDRESS}`, no domain is hardcoded; its host must match `APP_BASE_URL`'s host; fail-fast `${SITE_ADDRESS:?…}` on the caddy service), `MAIL_*` (real SMTP — defaults point at the dev MailHog, so email verification/login fails in prod without it), and storage. **Storage default is profile-driven, not set in compose**: `application-{cloud,dc}.properties` resolve `app.storage.type=${STORAGE_TYPE:s3}` (cloud) / `${STORAGE_TYPE:local}` (dc), so `STORAGE_TYPE` is only needed to override that per-model default; `STORAGE_S3_BUCKET`/`STORAGE_S3_REGION` are required when the effective type is s3. (Do NOT hardcode `STORAGE_TYPE` in compose — a forced value defeats the dc profile's local default.) The `app` service has a healthcheck (`wget` the public `/api/meta`, `start_period: 40s` for Spring Boot startup) and `caddy` waits on `condition: service_healthy`, so the proxy comes up only once the app is actually serving (no 502 window on `up`). Local-storage attachments persist in the `attachments_data` volume. Prod is served at https://hamstrack.com — DNS on Cloudflare (A records for `@`/`www`, **DNS only** / grey cloud; switching to the orange-cloud proxy requires SSL mode Full (strict)); Caddy auto-manages Let's Encrypt certs (persisted in the `caddy_data` volume). If the ghcr package is private, the server needs a one-time `docker login ghcr.io` with a PAT (`read:packages`).
